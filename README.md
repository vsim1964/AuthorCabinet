# Кабинет автора: чистый шаблон

Локальный рабочий кабинет для Windows 10. Тексты, история и вложения находятся на вашем компьютере. Вход через ChatGPT, подписка и внешний сервер не используются.

## Какая версия находится в этом репозитории

Основная ветка `main` содержит чистый шаблон `AuthorCabinet_Clean_Template` для любых книг. Здесь нет пользовательской базы, учебных рукописей, вложений и сохранённых версий. Последние изменения уже включены: текст редактора 16 px с интервалом 1,5, закреплённая панель форматирования и команды таблиц. Готовая сборка находится в `dist`; после получения обновлений пересобирать интерфейс не нужно.

`git pull` обновляет файлы программы, но не очищает папку `data` на вашем компьютере. Если после обновления вы видите прежнюю книгу, она загружается из местной базы, а не из GitHub.

Чтобы оставить именно эту папку чистым шаблоном, сначала сохраните текст и остановите кабинет через Ctrl+C в его консоли. Переместите папку `data` целиком в другое место, например в отдельную папку хранения прежних проектов. В ней находятся рукописи, версии, вложения и резервные копии. При следующем запуске программа создаст пустую базу и предложит «Создать проект». Перемещать данные работающего кабинета нельзя.

Для каждой новой книги копируйте файлы чистого шаблона в отдельную папку без `data`. Если требуется очистить только рабочую книгу, можно нажать «Создать проект» в интерфейсе и подтвердить замену: перед ней программа сохранит резервную копию.

## Запуск

1. Распакуйте весь архив в отдельную папку, например `C:\AuthorCabinet`. Не запускайте файлы прямо из ZIP. Выбирайте обычную локальную папку вне OneDrive и других каталогов синхронизации.
2. Дважды нажмите `START.bat`. Нужен установленный Node.js версии 22 или новее. Проверка версии в терминале: `node -v`.
3. Откроется браузер с адресом `http://127.0.0.1:4317`. Если браузер не открылся, скопируйте этот адрес вручную.
4. Пока работаете, оставьте окно консоли открытым. Закрытие браузера не останавливает программу.
5. Перед завершением работы нажмите «Сохранить» и дождитесь надписи «Сохранено на компьютере». Для остановки нажмите Ctrl+C в консоли.

В архив включены готовый интерфейс и зависимости сервера. Обычный запуск не требует интернета и установки Rust, Visual Studio либо дополнительных компонентов. Если папка `node_modules` удалена, файл запуска предложит скачать зависимости; для этого потребуется интернет.

## Повторное открытие и обновления

Если закрылась только вкладка браузера, снова запустите `START.bat`: он откроет страницу уже работающего кабинета. Второй сервер не создаётся.

После обновления кода сохраните текст кнопкой «Сохранить», дождитесь подтверждения и запустите `RESTART.bat`. Он проверит, что процесс относится к этой папке и является Node.js, остановит его и запустит обновлённую программу. Папка `data` и резервные копии не удаляются. Новые зависимости при необходимости устанавливаются автоматически; для этого шага нужен интернет.

Если экспорт сообщает «Не найдено» сразу после обновления, вероятная причина: браузер уже показывает новый интерфейс, а старый процесс сервера ещё работает. Используйте `RESTART.bat`, затем Ctrl+F5 в браузере.

## Чистый шаблон и создание проекта

В базовой комплектации нет рукописей, материалов, версий, демонстрационных книг и пользовательской базы. После запуска нажмите «Создать проект» и укажите название. Появится пустая книга; главы, заметки, планы и источники создаются отдельно.

Одна папка приложения соответствует одной книге. Храните исходный чистый шаблон отдельно. Для новой книги скопируйте шаблон в другую папку, запустите `START.bat` и создайте новый проект. В чистом архиве отсутствуют `data`, `backups` и `.git`, поэтому тексты и история предыдущих книг в новую папку не попадают. В этой версии одновременно запускайте одну папку приложения; перед открытием другой остановите текущую консоль через Ctrl+C.

Кнопка «Создать проект» доступна и в существующей книге. В этом случае нужно подтвердить замену: все рабочие материалы, версии, задачи, корзина и изображения заменятся новой пустой базой. Перед заменой создаётся резервный ZIP текущего проекта. Резервные архивы старой книги сохраняются в `data/backups`; они не входят в чистый шаблон. Чтобы получить папку совсем без прежних архивов, используйте чистый шаблон, а не копию уже заполненного приложения.

Изменение названия выполняется отдельной кнопкой «Изменить название» и ничего не очищает. Копирование файлов программы через Git не удаляет вашу локальную базу; для очистки уже установленного кабинета воспользуйтесь созданием нового проекта с подтверждением.

## Что работает

- Редактор: заголовки, жирный шрифт, курсив, подчёркивание, зачёркивание, цвета текста и выделения, ссылки, изображения, таблицы, индексы, списки, цитаты, выравнивание, отмена и повтор действий.
- Изображения PNG/JPEG/GIF/WebP до 5 МБ загружаются с компьютера и сохраняются локально. Удалённых картинок и сетевых шрифтов нет.
- Изменение таблицы: строки, столбцы, объединение и разделение ячеек.
- Автосохранение после паузы в редактировании, кнопка сохранения и страховочная копия несохранённых изменений в браузере.
- Авторские и автоматические версии. Восстановление создаёт версию текущего текста перед заменой.
- Сравнение по словам с подсветкой и сравнение оформления рядом.
- Задачи, заметки, примеры, чек-лист качества, фильтры статуса и типа материала.
- Поиск по сохранённому содержимому, названиям, заметкам и примерам.
- Импорт DOCX в один раздел или разделение по заголовкам первого уровня.
- Резервные ZIP-копии и восстановление проекта. Ежедневная копия создаётся при работающей программе; автоматически старые архивы не удаляются.
- Экспорт всех документов в HTML и TXT, всех изображений и структурированного проекта JSON с версиями и задачами.

## Корзина материалов

Над редактором есть кнопка «В корзину». Она сохраняет текущие правки и после подтверждения убирает открытый материал из оглавления. Текст, задачи, заметки и версии остаются в базе. Убранные материалы не участвуют в поиске, нумерации, публикационном экспорте и экспорте проекта HTML/TXT/JSON.

Кнопка «Открыть корзину» находится внизу бокового меню и показывает число материалов. В корзине можно восстановить материал: он возвращается в конец оглавления вместе с сохранёнными данными и историей. Обычное недельное ограничение для суточных версий продолжает действовать и в корзине; авторские версии сохраняются до окончательной очистки.

«Очистить корзину» требует отдельного подтверждения и удаляет из рабочей базы все перечисленные материалы и их версии, включая авторские. Перед очисткой автоматически создаётся резервный ZIP проекта. Существующие резервные архивы не изменяются. Файлы изображений в `assets` сохраняются, поскольку они могут использоваться в других материалах и версиях. Очистка не затрагивает активные главы и не выполняется автоматически.

Если другая вкладка изменила содержимое корзины после открытия подтверждения, очистка отменяется: сначала нужно проверить обновлённый список. Резервные копии содержат корзину, восстановление старых архивов поддерживается. При первом запуске обновления структуры базы создаётся резервная копия. Пустая книга после удаления всех материалов остаётся пустой. Автоматического добавления демонстрационных материалов нет.

## Порядок глав и нумерация

В оглавлении у каждого материала есть ручка перетаскивания и две кнопки со стрелками. Материал можно перетащить к верхней или нижней границе другой строки либо передвинуть кнопкой вверх/вниз. Жёлтая линия показывает место вставки. Стрелки работают и с клавиатуры.

Порядок сохраняется на диске, восстанавливается из резервной копии и используется при экспорте. Включённые фильтры не удаляют скрытые материалы из оглавления: перенос производится относительно видимого соседа в полном списке. Одновременное изменение порядка в другой вкладке вызывает обновление списка и просьбу повторить перенос.

Номера вычисляются автоматически по положению материалов типа «глава». Заметки, планы и источники не участвуют в нумерации. Номер показан в оглавлении и над названием открытой главы. При экспорте HTML/DOCX/TXT заголовки глав получают соответствующие номера, в том числе при экспорте отдельных выбранных глав. Авторский текст и сохранённые названия в базе автоматически не переписываются; старый числовой префикс в заголовке заменяется только в экспортной копии и отображении оглавления. Вложенное дерево частей и подглав в эту версию не входит.

## Экспорт книги или отдельных материалов

Кнопка «Экспорт» открывает выбор объёма и формата:

- «Вся книга» объединяет все материалы типа «глава» в порядке оглавления. Заметки, планы и источники сюда не входят.
- «Текущий материал» выгружает открытый раздел любого типа.
- «Выбранные материалы» объединяет отмеченные разделы любого типа в один файл в порядке оглавления.

Доступны HTML, DOCX и TXT. Перед экспортом текущие правки сохраняются; история версий, задачи и редакторские заметки в текст книги не добавляются.

HTML сохраняется одним автономным файлом со встроенными изображениями. Он открывается без работающего приложения. DOCX создаётся локально для Word и сохраняет основное оформление, уровни заголовков H1–H4, ссылки, списки, таблицы и поддерживаемые изображения. Сложная книжная вёрстка не гарантируется. Если изображение отсутствует или не может быть перенесено, экспорт сообщает об этом, а не молча пропускает его.

TXT содержит только текст: списки передаются строками, ячейки таблиц разделяются табуляцией, изображения заменяются обозначениями с подписями. Файл UTF-8 с BOM и окончаниями строк Windows предназначен в том числе для Блокнота.

Внизу окна экспорта остаётся «Архив проекта с историей и материалами (ZIP)»: это прежний полный экспорт HTML/TXT/JSON с вложениями, задачами и версиями. Для восстановления базы используйте резервный ZIP из отдельного окна «Резервные копии».

Для обновления с версии без DOCX остановите программу, выполните `git pull`, затем `npm ci --omit=dev` с интернетом и снова запустите `START.bat`. Готовый интерфейс уже включён в репозиторий, пересобирать его не требуется. Последующие экспорты работают полностью локально без интернета.

## Суточные и авторские версии

Автосохранение текущего текста продолжает работать после короткой паузы. История версий ведётся отдельно.

При первом сохранении изменённого текста в течение местных календарных суток создаётся одна суточная версия материала. Последующие сохранения в тот же день обновляют эту же запись. Она содержит последнее сохранённое состояние за день; новые строки истории при этом не создаются. Без изменений текста или оформления суточная версия не создаётся. Изменения задач, названия и чек-листа сами по себе версию не создают.

Суточные версии удаляются через семь суток после последнего обновления. Дополнительно хранится не более семи суточных записей на материал. Очистка выполняется при запуске, сохранении, открытии истории и раз в минуту, пока работает программа. Во время закрытия программа не выполняется; просроченные записи очищаются при следующем запуске. После очистки свободное место в SQLite уплотняется.

Версии, созданные кнопкой «Версия», хранятся бессрочно. Защитные версии перед восстановлением также сохраняются. Тип версии хранится отдельным полем: название, даже «Суточная версия», не делает авторскую версию автоматической.

Для старой базы перед обновлением структуры создаётся резервный архив. У старых версий не было достоверного признака способа создания, поэтому все они помечаются как «До обновления» и сохраняются бессрочно. Новое правило автоматической очистки применяется только к новым суточным версиям. Восстановление старых резервных архивов поддерживается с таким же безопасным преобразованием.

Срок хранения версий не удаляет резервные ZIP-архивы и не изменяет уже созданные копии. Они могут содержать более старую историю.

## Где лежат данные

Относительно папки приложения:

- `data/current/database.sqlite`: база данных с рукописью, материалами, задачами и всеми версиями.
- `data/current/assets`: изображения.
- `data/backups`: резервные ZIP-архивы.

Не редактируйте SQLite вручную при работающей программе. Изменять тексты и делать копии лучше через интерфейс. Для ручного переноса всей папки сначала остановите программу.

Кнопка «Экспорт» создаёт архив для чтения материалов другими программами. Кнопка «Резервные копии» создаёт архив для полного восстановления приложения. Это разные форматы. Резервная копия включает базу и изображения, но не установленный Node.js и не код программы. Храните также исходный архив приложения.

## Проверка восстановления

1. Создайте резервную копию и скачайте её на внешний носитель.
2. Зафиксируйте текущий текст кнопкой «Версия».
3. Внесите небольшое тестовое изменение и сохраните его.
4. В «Резервных копиях» выберите сохранённый ZIP и подтвердите восстановление.
5. Проверьте возвращение исходного текста. Состояние перед восстановлением останется отдельным резервным архивом.

## Границы первой версии

Это рабочий прототип, а не завершённая замена Word. В этой сборке одна рабочая книга с главами и материалами. Нет синхронизации, удалённого резервирования, шифрования архивов, режима принятия отдельных правок, сквозной библиографии, OCR и окончательной книжной вёрстки. Файлы и резервные копии не зашифрованы. Используйте защиту учётной записи Windows и диска, если она нужна.

Импорт DOCX передаёт структуру документа, основные выделения, таблицы, ссылки и встроенные изображения, но не гарантирует воспроизведения сложной вёрстки Word, текстовых полей, сносок и специфических стилей. Проверяйте сложные документы по оригиналу. Не поддерживаемые редактором элементы могут измениться после редактирования.

Программа слушает только `127.0.0.1`, не публикуется в интернете и не использует внешнюю авторизацию. Не открывайте её порт для локальной сети. Одна рабочая папка рассчитана на один запущенный процесс. При одновременном редактировании в двух вкладках конфликт версий останавливает перезапись, а интерфейс предлагает скачать несохранённый документ.

Страховочная копия браузера помогает после сбоя, но не заменяет сохранение на диск и резервный архив. Копия на том же диске не защищает от поломки этого диска.

Если после аварийного завершения перестал запускаться кабинет, сначала убедитесь, что старый процесс Node остановлен. Файл `data/server.lock` обычно очищается автоматически при новом запуске. Не удаляйте `data/current`.

## Оформление и закреплённая панель редактора

Основной текст редактора отображается размером 16 px с межстрочным интервалом 1,5. Панель форматирования закрепляется у верхнего края окна при прокрутке документа; команды работы с таблицей закрепляются вместе с ней. Высота панели учитывается при прокрутке к курсору, в том числе когда кнопки переносятся на несколько строк.

Исходные стили находятся в `src/style.css`. Приложение использует готовую сборку из `dist`, поэтому после изменения CSS выполните `npm run build` и обновите страницу через Ctrl+F5. Сам перезапуск не пересобирает интерфейс.

Если Vite не установлен, один раз выполните с интернетом `npm ci --include=dev`, затем `npm run build`. В GitHub обновляется и готовая сборка, поэтому для получения уже внесённых изменений пересобирать приложение на вашем компьютере не требуется.

## Для разработки в VS Code

Откройте папку проекта. Для установки полного набора зависимостей разработчика один раз выполните `npm ci` с интернетом. Затем:

- `npm start`: локальный сервер с готовым интерфейсом.
- `npm run dev`: интерфейс с обновлением при правках; локальный сервер также должен работать.
- `npm run build`: пересборка интерфейса в `dist`.
- `npm test`: проверки хранения, импорта, сохранения, конфликтов, версий, архивов и безопасности локальных запросов.

Технологии: React, JavaScript, Tiptap, Node.js, SQLite через sql.js, Mammoth, fflate. Rust и Tauri могут быть добавлены позднее для упаковки в отдельное настольное окно; текущая сборка использует браузер как интерфейс.

## Выполненная проверка

Сборка интерфейса и автоматические проверки выполняются в Linux с Node.js 24.22.1. Проверены хранение, версии, корзина, порядок глав, импорт, экспорт и создание пустого проекта с восстановлением предыдущего из копии. Тестовые DOCX создаются автоматически из искусственных проверочных абзацев; тексты книг в комплект не включены. Запуск на Windows 10 и работу в вашем браузере следует проверить на тестовом проекте.

## Ссылки на материалы проекта

Выделите текст, нажмите «Добавить ссылку» и выберите «Материал проекта». В списке доступны главы, заметки, планы и источники независимо от фильтров оглавления. Если ничего не выделено, вставляется название материала. Ссылки привязаны к идентификаторам и сохраняют назначение после переименования и перестановки глав.

В редакторе переход выполняется через Ctrl+щелчок (на macOS также Cmd+щелчок) либо кнопкой «Открыть материал» в окне ссылки. Перед переходом текущие изменения сохраняются. Удалённые материалы и содержимое корзины недоступны для перехода. Внешние ссылки по-прежнему можно вставлять по адресу. Внутренние ссылки предназначены для навигации внутри кабинета; экспортированные файлы не открывают материалы приложения.

## Перезапуск из терминала VS Code

В Windows откройте папку кабинета в VS Code и выполните `npm restart`. Команда работает из Git Bash, PowerShell и командной строки при стандартной настройке npm. Она вызывает `RESTART.bat`, который останавливает сервер этой папки и запускает кабинет снова. Перед перезапуском сохраните текст. Путь к диску в команде не нужен, поэтому после переноса папки команда остаётся прежней.

## Список материалов

Кнопка «Список материалов» слева открывает таблицу вместо редактора. В ней показаны название, тип, статус и дата изменения каждого материала в порядке оглавления. Поиск и фильтры слева действуют и на таблицу. Доступны создание материала, открытие редактора, изменение типа и перемещение в корзину с подтверждением. Перед переключением текущий текст сохраняется. Изменение типа сохраняет текст, задачи и версии и обновляет нумерацию глав.

## Теги материалов

Под названием материала находится поле «Теги». Введите тег и нажмите Enter или «Добавить тег». Несколько тегов можно разделить запятыми; удалить тег можно крестиком рядом с ним. Теги видны в материале и отдельной колонке списка материалов, сохраняются вместе с проектом, корзиной и резервными копиями. До 30 тегов на материал, до 80 символов каждый; повторные теги без учёта регистра не добавляются. При открытии прежней базы программа создаёт резервную копию и добавляет поддержку тегов.
